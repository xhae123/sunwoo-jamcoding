# 오늘 뭐하지 — 분당 서현동

> **아침에 눈 뜨면 딱 하나가 궁금하다. "오늘 뭐하지?"**
> 그 질문에, 오늘 날씨를 읽고 우리 동네에서 할 만한 걸 골라 답해주는 하루짜리 웹.

기상청 실시간 예보를 받아, 분당 서현동에서 **오늘 날씨에 딱 맞는 하루**를 매일 새로 큐레이션합니다.
결과는 극심플·모던한 HTML 한 장으로 로컬에 차곡차곡 쌓입니다.

## 이 프로젝트는요

**잼코딩(JamCoding) 학원 재원생 프로젝트입니다.**
재원생 **선우**가 "진짜 돌아가는 서비스"를 처음부터 끝까지 만들어보는 학습 프로젝트예요.
장난감 예제가 아니라 — 실제 공공 API를 붙이고, 데이터를 다루고, 화면까지 뽑아내는 **완결형 미니 제품**을 목표로 합니다.

---

## 뭘 하는 서비스인가

1. 오늘 아침, 기상청에서 **분당 서현동 날씨**를 가져온다 (기온·하늘·강수·습도·바람)
2. 날씨의 흐름을 하루의 이야기로 읽는다 — *"오후 소나기 → 저녁엔 갬"* 같은
3. 그 흐름에 맞춰 서현동에서 할 만한 걸 **3~5개** 고른다 (실내/실외를 날씨에 맞게)
4. 이유(왜 하필 오늘 이걸?)와 함께 예쁜 페이지로 뽑는다
5. 매일 한 장씩, 로컬에 아카이브처럼 쌓인다

같은 날 다시 돌리면? **이미 있으면 건너뛴다.** 하루엔 하루의 큐레이션만.

---

## 어떻게 만들어졌나 (핵심 설계)

이 프로젝트의 심장은 **역할을 둘로 나눈 것**입니다.

| | 담당 | 하는 일 | 성격 |
|---|---|---|---|
| **배관 (Python 스크립트)** | 기계 | 날씨 fetch·파싱, HTML 렌더링 | 매번 **똑같이** 동작해야 함 |
| **큐레이션 (AI)** | Claude | 날씨 읽고 서현동 추천 창작 | 매일 **달라야** 함 |

> **왜 나눴나?** 날씨를 활동에 기계적으로 매핑하면 매일 똑같은 뻔한 결과("맑음→산책")가 나옵니다.
> 그래서 *변하면 안 되는 것*(데이터 처리·디자인)은 코드에 고정하고,
> *매일 새로워야 하는 것*(추천 문장·이유)은 AI가 창작하게 했습니다. 이 분리가 "핫바지 서비스"를 막는 장치예요.

## 폴더 구조

```
sunwoo-jamcoding/
├── index.html              ← 시작점. 지금까지 쌓인 하루들 (최신순)
├── pages/
│   └── 2026-07-04.html     ← 하루 페이지 한 장
├── data/
│   └── 2026-07-04.json     ← 그날의 원본 (날씨 + 큐레이션). 다시 그릴 때 쓰는 재료
└── assets/
    └── style.css           ← 공유 디자인 (매 렌더마다 새로 씀)
```

## 배운 것들 (재원생 학습 포인트)

- 공공 API는 어떻게 인증하고, 응답(XML)을 어떻게 파싱하는가
- "지금 기온"을 정적 페이지에 박으면 왜 거짓말이 되는가 → **업데이트 시각으로 고정**
- 왜 데이터(`data/`)와 화면(`pages/`)을 분리하나 → 재료를 남겨두면 **디자인만 바꿔 다시 그릴 수 있다**
- 같은 날 두 번 돌려도 안전하게 (멱등성)
- **"빌드 성공"이 출시 기준이 아니다.** "첫 유저가 열면 재미있는가"가 기준이다
